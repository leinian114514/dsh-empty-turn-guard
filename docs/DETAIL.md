# 空转守卫

模型偶尔会出现一种"假完成"：一个回合里它只输出了思考，**正文一个字没有、工具一个没调**，
界面却显示「已完成」。你看到的是"它想了一下就说做完了"，其实什么都没干。

这个插件专门接住这种情况。

## 它看到的和 DSH 自己看到的不一样

DSH 本身有 `EMPTY_RESPONSE` 机制（在默认重试列表里，最多重试 5 次），但它的判据是
`content.length === 0`——**一个内容块都没有**。而空转的消息里**有 reasoning 块**，
在它眼里这叫"有内容"，于是静默通过。这道缝就是本插件补的那一格。

判据因此是三条一起看：**有 reasoning、没有 text、没有 tool-call**。

## 怎么发现的（这条踩过弯路，写清楚）

最初想用 `assistant/message` 事件配合 `agent/created` 做 per-agent 注册。
**实测走不通**：`assistant/message` / `turn/end` 在插件根上下文上挂得上，但一条都不触发。

真正能用的是 **`agent/assistant-stream`**：payload 是 `{agent, frame}`，
frame 有 `start` / `chunk`，chunk 分 `reasoning-delta` / `text-delta` / `tool-call-delta` 三种。
每次 `start` 开启一次新的 attempt，所以在 start 时重置、只留最后一次尝试的累积——
这就是"最后一条 assistant 消息"的等价物。

同一个钩子本机另一个插件（`dsh-thinking-guard`）在用且工作正常，是可靠参照。

## 发现之后做什么

- 先让它**重做一次**（用 `followup` 唤醒，而不是等你发现）
- 同一个回合里只自动重做一次；第二次还空，就把控制权还给你，不在后台无声烧轮次
- 连续撞到上限（默认 3 次）就彻底停手并记一条警告
- **被中断的回合不算空转**：你自己按了停，插件不该替你重试
  （实测这条是上游保证的——abort 时 `turn-stopping` 根本不会派发）

## 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `maxConsecutive` | `3` | 连续空转多少次后彻底停手 |
| `minReasoningChars` | `0` | 思考至少多少字才算空转。**建议保持 0** |
| `debugFile` | `''` | 日志落盘路径。桌面版 `ctx.logger` 不一定看得到，自用建议设上 |

### 为什么 `minReasoningChars` 默认是 0

上线第一天它就教训了一次：门槛设 40，真机上一次**思考 39 字、正文和工具都没有**的空转
被放过去了——差 1 个字。降到 10 之后审计指出还有一格：**思考不到 10 字 + 无正文 + 无工具**，
这一格插件不催、DSH 也不重试（它的判据是零内容块，reasoning 算内容），**100% 漏掉**。

而正常回合一定有正文或工具调用。"两样都没有"本身就是异常，跟思考了多久无关。
所以门槛只保留"reasoning 不为空"这一个下限，不再拿字数区分。

## 限制（如实写）

- 只认"最后一步"：一个回合里如果先空转、后面又干了活，不会误报（最后一条有产出就不算）。
- 判据依赖消息里确实带 `reasoning` 块、且正文以 `text-delta` 下发。
  如果底层改成"正文只出现在 `block-end` 里"，插件会**误报**空转。
- 如果 DSH 把 `assistant-stream` 的 payload 形状改了（不再带 `agent`、或 chunk 类型改名），
  插件会**静默失效**——不崩、也不报，只能从日志里每回合那行「思考 0 字 / 正文 0 字」看出来。
- 它不修复模型本身，只是把"假完成"变成"再试一次 / 明确交还控制权"。
